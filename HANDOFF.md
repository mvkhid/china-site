- Сайт на GitHub Pages запрашивает курс у Cloudflare Worker по HTTP на клиенте (в браузере), с фолбэком на последний известный корректный курс при сбое сети/парсинга.

**История миграций хостинга сайта** (для будущего — не повторять эти шаги):
1. **Vercel** (изначальный план) — работал технически, но оказался недоступен для реальных посетителей из российских мобильных сетей (МТС, Мегафон — ни с VPN, ни без). Вероятная причина — коллатеральная блокировка общих IP-диапазонов Vercel в РФ.
2. **Cloudflare Worker (custom domain)** — настроили как замену, но наткнулись на баг с `Content-Encoding: zstd` (Cloudflare сжимал ответ в Zstandard, Safari и часть прокси-серверов мобильных операторов не могли это декодировать — страница зависала в состоянии "loading" навечно). Почасти чинили (Compression Rule → Brotli вместо zstd, отключали HTTP/3), но проблема оказалась глубже уровня протокола, и решили просто уйти с Cloudflare-прокси для сайта.
3. **GitHub Pages** (финальный выбор) — максимально простой, "скучный" static hosting, никакой экзотики в сжатии/протоколах. Исходники там отдаются из отдельной ветки `gh-pages` в этом же репозитории (НЕ `main`) — это осознанно отдельная git-история (создана как самостоятельный репозиторий внутри `site/out/`, не связана commit-ами с `main`). Деплой — вручную: `cd site && npx next build && cd out && git add -A && git commit -m "..." && git push origin gh-pages`. Если GitHub Pages «зависнет» (не публикует/нет SSL больше ~30 мин) — помогает пустой коммит (`git commit --allow-empty`) в `gh-pages`, это форсирует пересборку.

**Worker автокурса задеплоен и работает:** `https://reseller-rate-worker.mgmdgdjiev1.workers.dev` — `GET /rate` отдаёт текущий курс, cron тикает каждые 15 мин, парсер проверен на множестве реальных постов. Код в `worker-rate/` в этом репозитории.

**Источник истины по дизайну** — файл `preview-opt.html` (загружается вместе с этим документом). Весь CSS, вся разметка, все анимации, тексты и вшитые картинки — там. Ничего не придумывать заново, переносить как есть.

## 3. Технический стек (GitHub Pages + Cloudflare Worker)

**Сайт:**
- **Next.js 15** (App Router), но собирается в **статический экспорт** (`next.config.mjs` → `output: "export"`) — никакого сервера, ни одной серверной функции, всё prerendered на этапе сборки
- Деплой — **GitHub Pages**, из ветки `gh-pages` (отдельная git-история, не связана с `main` — см. раздел 0)
- **Framer Motion** — анимации (в макете они на чистом CSS+IntersectionObserver, при переносе можно оставить как есть или перевести на Framer Motion)
- **Шрифт Jost** (Google Fonts, веса 300/400/500/600/700, subset cyrillic+latin)

**Пайплайн автокурса (отдельный сервис на Cloudflare):**
- **Cloudflare Worker** — маленький сервис, не связан с хостингом сайта
- **Cloudflare KV** (`RATE_KV`) — хранит распарсенный курс
- **Cloudflare Cron Trigger** — каждые 15 минут парсит канал, обновляет `RATE_KV`
- Worker отдаёт `GET /rate` — публичный JSON-эндпоинт с CORS-проверкой хоста (`reseller-china.ru` / `www.reseller-china.ru`, любая схема), его читает сайт с клиента (в браузере, не на сервере — сервера у статического сайта нет)

**Репозиторий:** `mvkhid/china-site` на GitHub (НЕ старый `mvkhid/-1` — тот не трогали, там прошлая версия проекта). Ветка `main` — исходники (Next.js проект, Cloudflare Worker), ветка `gh-pages` — собранная статика для хостинга.

### Как устроен перенос дизайна в `site/` (прагматичное решение под дедлайн)

Вся разметка `preview-opt.html` использует инлайновые `onclick="..."` и глобальные JS-функции (`showPage()`, `openPrivacy()` и т.д.) — это типичный vanilla-JS паттерн, который не транслируется напрямую в JSX (`onclick` как строка — не то же самое, что React `onClick={fn}`). Чтобы перенести «как есть» без риска внести опечатки при ручной конвертации 1675 строк разметки в JSX под сжатые сроки, сделано так:

- `site/lib/legacy-markup.html` — вся разметка (header → footer → модалки → lightbox) как есть, один raw HTML-блок
- `site/lib/legacy-script.js` — оба `<script>` блока из макета, с точечными правками:
  - `tiers` теперь `let` и подтягивается из `GET /rate` (см. `loadLiveRate()`), с хардкодом как фолбэком
  - инициализация переведена с `DOMContentLoaded` на `onDomReady()` — в Next.js скрипт грузится через `<Script strategy="afterInteractive">`, то есть **после** `DOMContentLoaded`, и обычный listener на это событие никогда не сработает
- `site/app/page.js` — server component, рендерит markup через `dangerouslySetInnerHTML` и скрипт через `next/script`
- `site/app/globals.css` — CSS из макета, перенесён без изменений
- Картинки (7 чеков + фото) вынесены из base64 в `site/public/` скриптом `extract.mjs` (в корне репозитория, разовый — можно удалить)

Это не «правильный» React (компонентов нет), но работает полностью корректно и соответствует требованию HANDOFF «ничего не придумывать заново, переносить как есть». Разбить на компоненты можно позже, не блокирует запуск.

## 5. Калькулятор — логика (перенести точь-в-точь)

```js
const tiers = [
  {threshold:1,     rate:11.75},
  {threshold:1000,  rate:11.60},
  {threshold:30000, rate:11.55}
];
```

**Важно:** направление только одно — **рубли → юани**. Кнопка свапа удалена намеренно (обратный обмен идёт по другому курсу, чтобы не вводить в заблуждение). Вместо неё статичная стрелка `→` (на мобайле поворачивается на 90°).

Логика:
1. Пользователь вводит сумму в рублях
2. Пересчитываем в юани, по полученной сумме выбираем тарифную ступень (`pickTier`)
3. Результат = рубли / курс ступени
4. Подсвечиваем активную ступень классом `.tier-active`
5. В `#active-info` пишем «Применён курс X ₽ за 1¥ · ступень от N¥»
6. В `#upsell` — подсказка «от N¥ выгоднее — X ₽» (если есть следующая ступень)
7. Кнопка «Оформить заявку» формирует deeplink в Telegram с подставленной суммой:
   `https://t.me/mvkhid?text=Здравствуйте! Нужна оплата 11750₽ → 1012,93¥ по курсу 11,60`

Форматирование чисел — `Intl.NumberFormat('ru-RU')`, 2 знака после запятой.

**При переносе:** ставки `tiers` должны приходить из `RATE_KV`, а не быть захардкожены. Захардкоженные значения в макете — фолбэк/пример.

## 6. Автокурс — главная фича, требует реализации

**Это ядро проекта.** Сейчас в макете курс вшит статикой. Нужно поднять цепочку:

```
Telegram @reseller_rmb → Cloudflare Cron (каждые 15 мин) → парсинг поста → RATE_KV → GET /rate → сайт (Vercel)
```

### Что нужно реализовать

1. **Cron Trigger** в `wrangler.toml` (Cloudflare Worker) — каждые 15 минут
2. **Парсер** — забирает последний пост с курсом из канала. Варианты источника:
   - публичный HTML `https://t.me/s/reseller_rmb` (без бота, но формат хрупкий)
   - Telegram Bot API (бот должен быть админом канала)
3. **Извлечь три ставки:** от 1¥, от 1000¥, от 30000¥ + дату публикации
4. **Записать в `RATE_KV`** JSON вида:
   ```json
   {
     "tiers": [
       {"threshold": 1, "rate": 11.75},
       {"threshold": 1000, "rate": 11.60},
       {"threshold": 30000, "rate": 11.55}
     ],
     "publishedAt": "2026-09-13T10:00:00+03:00",
     "updatedAt": "2026-09-13T10:15:00+03:00"
   }
   ```
5. **Worker отдаёт `GET /rate`** (JSON из KV, публичный, CORS открыт для домена сайта) — Next.js-сайт на Vercel запрашивает его при рендере и отдаёт в калькулятор + в подписи «Курс безналичного обмена · 13.09» и «обновлено · 13 сентября в 10:00»

### ⚠️ Обязательная подстраховка

Если формат поста в канале изменился или парсинг упал — **не показывать неверный курс**. Держать последний корректный из KV и логировать ошибку. Курс на сайте, не совпадающий с реальным, хуже чем слегка устаревший.

### ❗ Известная проблема
На прошлом live-адресе автокурс сломан — показывает майский курс. Причина не выяснена (cron не запускается / изменился формат поста / не пишет в KV / сайт не читает). При сборке заново проверить всю цепочку и залогировать каждый шаг.

## 10. Тексты — не «улучшать»

Тексты специально вычищены от ИИ-штампов и написаны голосом владельца. **Не переписывать, не «причёсывать», не добавлять от себя** блоков вроде «Всё легально и прозрачно», «за N секунд», «коротко о главном».

Что было убрано намеренно и не должно вернуться:
- любые упоминания **USDT**
- «Посчитайте сумму за 5 секунд», «Юани для разных задач», «Коротко о главном», «Чтобы вы были спокойны»
- канцелярит «обрабатываю по возможности»

Блоки сознательно сделаны **разноформатными** (чипы / кружки с цифрами / вертикальная линия слева / аккордеон / крупные цифры) — чтобы сайт не читался как ИИ-шаблон. Не унифицировать в одинаковые карточки.

**Мелочь, но важно:** при добавлении любых новых картинок — переименовывать файлы осмысленно (`icon-telegram.png`, а не `ChatGPT_Image_22.png`). Чистый код = солиднее.

## 11. Мобильная версия — вылизана, не сломать

Много точечных правок под мобайл, все в медиазапросах макета. Ключевое:

- Шрифты подогнаны по всем страницам (hero-заголовок `clamp(2.2rem,9vw,2.8rem)`, лиды `.95rem`, подписи `.82-.88rem`)
- Тарифные ступени калькулятора — вертикальным списком (слева «от 1¥», справа ставка)
- Нижний навбар `.demo-switch` — уменьшенные padding/шрифт, `white-space:nowrap` жёстко, чтобы «Как работает» не переносилось
- Cookie-баннер — кнопки в ряд, компактный
- Мини-статы — 3 колонки, текст по центру
- «Где закупаю» — 2 колонки (1 колонка на `<400px`)
- Футер — в столбик по левому краю
- Blob-эффект на touch **отключён**
